# Event calendar

This guide covers the **event calendar**: `Calendar` from
`@itclabs/react-ui/calendar`, also exported as `EventCalendar` from
`@itclabs/react-ui`. The root `Calendar` is the date-selection grid used by
`DatePicker`.

The event calendar provides Month, Week, Day and List views. Your application owns
events, range loading, permissions and persistence. It uses local time;
**recurrence, time-zone configuration and resource timelines are not implemented yet**.

Try [Modules/Calendar](?path=/docs/modules-calendar--docs) or
[Templates/CalendarPage](?path=/story/templates-calendarpage--playground) for an
example with WorkspaceShell, Sidebar, PageHeader, Dialog and Drawer.

## Imports and event data

Import styles once in your application, as described in
[Getting started](?path=/docs/overview-getting-started--docs). No provider is
required; the default locale is Vietnamese. Use `UIProvider locale="en-US"` for
English labels and formatting (see Localization below).

Every `end` is **exclusive**: an event ending at midnight does not occupy the next
day. Date-only ISO strings are parsed at local midnight. An omitted `end` defaults
to one hour for timed events or one day for all-day events. IDs must be stable and
unique.

```tsx
import { Calendar, type CalendarEvent } from '@itclabs/react-ui/calendar';

const events: CalendarEvent[] = [
  {
    id: 'alpha',
    title: 'Lorem ipsum',
    start: '2026-10-29T09:00',
    end: '2026-10-29T10:00',
    tone: 'info',
  },
  {
    id: 'beta',
    title: 'Dolor sit amet',
    start: '2026-10-28',
    end: '2026-10-30',
    allDay: true,
    tone: 'success',
  },
];

export function BasicCalendar() {
  return (
    <Calendar
      events={events}
      defaultDate={new Date(2026, 9, 29)}
      defaultView="month"
      dayMaxEvents={3}
      data-testid="schedule"
    />
  );
}
```

## Views and display options

| Prop                            | Behavior                                                                                                                                        |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `views`                         | Nonempty list of enabled views; defaults to `month`, `week`, `day`, `list`.                                                                     |
| `weekLayout`                    | Week uses `timeGrid` by default; choose `dayGrid` for a row of dates. Day always uses a time grid.                                              |
| `fixedWeekCount`                | Month shows six weeks by default; `false` uses only the weeks needed for that month.                                                            |
| `dayMaxEvents`                  | Limits visible event levels in date grids and the all-day row; overflow opens a popover. Omitted means unlimited.                               |
| `weekNumbers`                   | Shows localized ISO week numbers in Month and day-grid Week.                                                                                    |
| `slotDuration`                  | Positive whole minutes dividing 1440; defaults to 30.                                                                                           |
| `slotMinTime`, `slotMaxTime`    | Visible local time window in `HH:mm` or `HH:mm:ss`; defaults to `00:00`–`24:00`.                                                                |
| `businessHours`                 | Shades nonbusiness time. `true` means Monday–Friday, 09:00–17:00; custom schedules are supported. This is a visual aid, not a permission check. |
| `nowIndicator`                  | Shows the current local time, updated each minute; defaults to `true`.                                                                          |
| `toolbarStart`, `renderToolbar` | Add an action before Today, or replace the toolbar. Return `null` from `renderToolbar` to hide it.                                              |

## Controlled navigation

Control `date` and `view` independently, or use `defaultDate` and `defaultView`
for internal state. Controlled callbacks propose values; pass those values back
through props to commit navigation. A controlled `view` must be included in `views`.

`onRangeChange` reports the committed visible range, including neighboring dates
in Month and the effective view when `responsiveView` is active. Its end is
exclusive. React StrictMode can repeat mount effects, so loading must tolerate
repeated requests.

```tsx
'use client';
import { useState } from 'react';
import { Calendar, type CalendarView } from '@itclabs/react-ui/calendar';

export function ControlledCalendar() {
  const [date, setDate] = useState(new Date(2026, 9, 29));
  const [view, setView] = useState<CalendarView>('week');
  return (
    <Calendar
      date={date}
      onDateChange={setDate}
      view={view}
      onViewChange={setView}
      views={['month', 'week', 'day', 'list']}
    />
  );
}
```

## Load events by range

Pass an application-owned loader and keep previous events visible while `loading`.
Request events that overlap the range (`event.start < range.end` and
`event.end > range.start`), including events that started before it.

The effect below aborts requests on range changes or unmount and ignores stale
results even if the loader does not honor the signal. Changing only the
`onRangeChange` callback identity does not emit another range notification.
Keep `loadEvents` stable (declare it outside the component or use `useCallback`)
to avoid restarting the loading effect unnecessarily.

```tsx
'use client';
import { useEffect, useState } from 'react';
import {
  Calendar,
  type CalendarEvent,
  type CalendarRangeChange,
} from '@itclabs/react-ui/calendar';

type LoadEvents = (
  range: CalendarRangeChange,
  signal: AbortSignal,
) => Promise<CalendarEvent[]>;

export function RemoteCalendar({ loadEvents }: { loadEvents: LoadEvents }) {
  const [range, setRange] = useState<CalendarRangeChange | null>(null);
  const [events, setEvents] = useState<CalendarEvent[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState('');
  useEffect(() => {
    if (!range) return;
    const controller = new AbortController();
    setLoading(true);
    setError('');
    void (async () => {
      try {
        const result = await loadEvents(range, controller.signal);
        if (!controller.signal.aborted) setEvents(result);
      } catch {
        if (!controller.signal.aborted) setError('Unable to load events.');
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    })();
    return () => controller.abort();
  }, [range, loadEvents]);
  return (
    <>
      {error && <p role="alert">{error}</p>}
      <Calendar events={events} loading={loading} onRangeChange={setRange} />
    </>
  );
}
```

## Select a range to create an event

`selectable` enables drag selection; touch requires a 300ms hold, and Escape
cancels. Shift+Enter or Shift+Space selects the focused cell. `selectAllow` can
reject a range. Selection only calls `onSelect`; your application creates the event.
This example opens a Dialog, asks for a title and preserves the exclusive end.
See [Overlays & feedback](?path=/docs/guides-overlays-feedback--docs) for overlay patterns.

```tsx
'use client';
import { useState } from 'react';
import { Button, Dialog, Input } from '@itclabs/react-ui';
import {
  Calendar,
  type CalendarEvent,
  type CalendarSelect,
} from '@itclabs/react-ui/calendar';

export function CreateCalendar() {
  const [events, setEvents] = useState<CalendarEvent[]>([]);
  const [selection, setSelection] = useState<CalendarSelect | null>(null);
  const [title, setTitle] = useState('');
  return (
    <>
      <Calendar
        events={events}
        selectable
        onSelect={(range) => {
          setTitle('');
          setSelection(range);
        }}
      />
      <Dialog
        title="New event"
        description="Enter an event title."
        open={selection !== null}
        onOpenChange={(open) => {
          if (!open) setSelection(null);
        }}
      >
        <form
          className="space-y-4"
          onSubmit={(event) => {
            event.preventDefault();
            if (!selection || !title.trim()) return;
            setEvents((current) => [
              ...current,
              {
                id: crypto.randomUUID(),
                title: title.trim(),
                start: selection.start,
                end: selection.end,
                allDay: selection.allDay,
              },
            ]);
            setSelection(null);
          }}
        >
          <Input
            label="Event title"
            value={title}
            onChange={(event) => setTitle(event.target.value)}
            required
          />
          <Button type="submit">Create event</Button>
        </form>
      </Dialog>
    </>
  );
}
```

## Drag, resize and optimistic editing

`editable` enables moving and resizing in Month, Week and Day; List does not
support editing. Per-event flags take precedence: `startEditable` for moving or
`durationEditable` for resizing, then `event.editable`, then calendar `editable`.
`eventAllow` checks both previews and commits. In time grids, dragging between the
all-day row and timed slots changes `allDay`. Drag the end handle to resize the
exclusive end.

The calendar displays a pending proposal while you save. **Keep the same `events`
array until saving succeeds**: replacing it clears all pending proposals. On
failure, call `revert()` and report the error. `revert()` restores the calendar's
pending edit; it does not update application state that you have already changed.

This example serializes saves so replacing the array cannot discard another
pending proposal. Validate permissions again in your persistence layer.

```tsx
'use client';
import { useRef, useState } from 'react';
import {
  Calendar,
  type CalendarEvent,
  type NormalizedEvent,
} from '@itclabs/react-ui/calendar';

type SaveEvent = (event: NormalizedEvent) => Promise<void>;

export function EditableCalendar({
  initialEvents,
  saveEvent,
}: {
  initialEvents: CalendarEvent[];
  saveEvent: SaveEvent;
}) {
  const [events, setEvents] = useState(initialEvents);
  const [error, setError] = useState('');
  const saving = useRef(false);
  return (
    <>
      {error && <p role="alert">{error}</p>}
      <Calendar
        events={events}
        defaultView="week"
        editable
        eventAllow={() => !saving.current}
        onEventChange={async ({ event, revert }) => {
          saving.current = true;
          setError('');
          try {
            await saveEvent(event);
            setEvents((current) =>
              current.map((item) => (item.id === event.id ? event : item)),
            );
          } catch {
            revert();
            setError('Unable to save changes. Event restored.');
          } finally {
            saving.current = false;
          }
        }}
      />
    </>
  );
}
```

`revert()` is idempotent. A stale callback cannot undo a newer edit or an application
array update. Try [OptimisticUpdate](?path=/story/modules-calendar--optimistic-update)
for a simulated failure with a toast, or [Keyboard](?path=/story/modules-calendar--keyboard)
for commit and cancel behavior.

## Custom event content

`renderEvent` receives a normalized event (`Date` boundaries and a boolean
`allDay`), `view`, `timeText`, `isStart` and `isEnd`. Return noninteractive content:
the outer event chip owns semantics, focus and edit handles. Generic `data`
preserves your application's type. `tone` uses theme tokens; `color` changes only
the accent, preserving readable background and text colors.

```tsx
import { Calendar, type CalendarEvent } from '@itclabs/react-ui/calendar';

const events: CalendarEvent<{ note: string }>[] = [
  {
    id: 'alpha',
    title: 'Lorem ipsum',
    start: '2026-10-29T09:00',
    data: { note: 'Dolor sit amet.' },
  },
];

export function CustomEvents() {
  return (
    <Calendar
      events={events}
      defaultDate={new Date(2026, 9, 29)}
      renderEvent={({ event, timeText }) => (
        <span>
          <strong>{event.title}</strong> · {timeText}
          <span className="block text-small">{event.data?.note}</span>
        </span>
      )}
      eventClassName={({ event }) => (event.allDay ? 'font-semibold' : 'border-l-4')}
      onEventClick={({ event }) => console.log(event.id)}
    />
  );
}
```

## Localization and week start

`UIProvider` controls translated labels and locale-aware `Intl` formatting.
Without a `weekStartsOn` prop, the calendar uses the resolved calendar locale's
week start: Vietnamese starts on Monday, while English uses Sunday. For other
locales, configure `UILocale.calendarLocale` or the provider's `calendarLocales`;
see [Localization](?path=/docs/guides-localization--docs).

The example follows the English locale's Sunday start. To override it, add
`weekStartsOn={1}` for Monday (`0` = Sunday through `6` = Saturday). Pure engine
helpers such as `viewRange` default to Monday independently of React; pass
`weekStartsOn` explicitly when calculating matching ranges outside the component.

```tsx
import { UIProvider } from '@itclabs/react-ui';
import { Calendar } from '@itclabs/react-ui/calendar';

export function EnglishCalendar() {
  return (
    <UIProvider locale="en-US">
      <Calendar weekNumbers defaultView="week" />
    </UIProvider>
  );
}
```

## Keyboard and interaction states

| Focus or state                     | Keys                                     | Behavior                                                                                                                                                                                   |
| ---------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Toolbar                            | Tab; arrow keys within view tabs         | Navigate controls and switch views. Below the `sm` breakpoint, the view switcher is a dropdown menu.                                                                                       |
| Month / day-grid Week cell         | Arrow keys; Home/End; PageUp/PageDown    | Move by date/week, jump to the first/last date of the row, or move a month. When navigation crosses the displayed period, a controlled application must commit `date` for focus to follow. |
| Timed slot                         | Arrow keys; Home/End                     | Move between slots/days within the range, or jump to the start/end of the time window.                                                                                                     |
| Date or timed cell                 | Enter/Space; Shift+Enter/Space           | Call `onDateClick`; select one cell when `selectable`.                                                                                                                                     |
| Editable event                     | Enter, arrows, Shift+arrows, Enter       | Pick up, preview a move, preview a resize, then commit once. Left/right changes dates; up/down changes slots (or dates in day grids and all-day rows).                                     |
| Active edit                        | Escape; Tab                              | Cancel; cancel and continue moving focus. A live region announces the range and exclusive end.                                                                                             |
| Event / resize handle              | Alt+arrows                               | Move immediately; focus the resize handle to resize immediately.                                                                                                                           |
| Clickable event                    | Space; Enter when editing is unavailable | Call `onEventClick`. Enter starts editing when editing is available.                                                                                                                       |
| Overflow popover / Dialog / Drawer | Escape                                   | Close the overlay and restore focus.                                                                                                                                                       |

`loading` blocks content interactions while keeping toolbar navigation available;
`disabled` blocks the entire calendar. During a keyboard preview, focus stays on
the source event. After a commit it follows a visible segment; if the event leaves
the range, focus returns to the calendar region. `onEventClick` can open a Drawer,
as shown in CalendarPage.

## Sizing and customization

`height` sets the root height and accepts a number of pixels or a CSS height value.
The time grid scrolls within its content area (with a default maximum height of
40rem). `scrollTime` sets the initial local scroll position, defaults to `06:00`,
and is clamped to the visible time window. Dense overlapping events widen the
scrollable canvas to keep event columns readable.

`responsiveView="list"` or `responsiveView="day"` switches the effective view when
the **container** is narrower than 640px, then restores the selected view when it
widens. This is separate from the toolbar's breakpoint-based view switcher.

Use `className` on the root and typed `classNames` for individual slots; see
[Customization](?path=/docs/guides-customization--docs) and
[Theming](?path=/docs/guides-theming--docs). `ref` points to the root div through the
React 19 ref prop. `data-testid` supplies a base ID; part IDs are generated only
when a base is provided.

Verify focus, touch selection, overlays and narrow layouts in a browser.
A Storybook build alone does not run story play functions.
