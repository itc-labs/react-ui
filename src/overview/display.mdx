# Data display

Use `CodeView` for read-only source, `JsonView` for inspecting structured values, and `Carousel` for browsing a sequence of items. Import CodeView and Carousel from their dedicated subpaths to keep Prism and Embla out of the core entry. Rating is available from the root; see [Forms](?path=/docs/guides-forms--docs) for a score field.

## CodeView

Supply source through `code` and choose a `language`. `title` takes precedence over `filename`. Line highlights accept one-based numbers and inclusive ranges; `wrap` and `maxHeight` control long content. The copy button copies the original source and announces success through localized feedback. Tab reaches the copy button and the scroll region.

```tsx
import { CodeView } from '@itclabs/react-ui/code-view';

export function SourceExample() {
  return (
    <CodeView
      code={'export function example() {\n  return "Lorem ipsum";\n}'}
      language="ts"
      filename="example.ts"
      showLineNumbers
      highlightLines={[1, '2-3']}
      wrap
      maxHeight={320}
    />
  );
}
```

See [CodeView stories](?path=/docs/modules-codeview--docs) for supported languages and styling slots.

## JsonView

Pass a value through `data`; `rootName` labels the tree. Root depth is zero, so `defaultExpandDepth={1}` initially opens the root, while `true` opens all containers. `sortKeys` sorts object keys, and `collapseStringsAfter` adds inline expansion for long strings. Arrow keys navigate and expand the tree; Home and End move to its first and last visible rows. The copy button copies the complete value, including collapsed content.

```tsx
import { JsonView } from '@itclabs/react-ui';

export function StructuredValueExample() {
  return (
    <JsonView
      data={{
        title: 'Lorem ipsum',
        count: 0,
        enabled: false,
        items: [{ id: 'first', description: 'Dolor sit amet' }],
      }}
      rootName="Response"
      defaultExpandDepth={1}
      sortKeys
      collapseStringsAfter={80}
      maxHeight={320}
    />
  );
}
```

See [JsonView stories](?path=/docs/components-jsonview--docs) for expansion and extended-value rendering.

## Carousel

Provide `items`, a stable `getItemKey`, and `renderItem`. `perView` accepts a column count or responsive counts at Tailwind breakpoints; `rows` stacks items in each column. `index`, `defaultIndex`, and `onSlideChange` address zero-based scroll snaps, including dots. Keep `index` synchronized with `onSlideChange` when controlling selection.

```tsx
import { useState } from 'react';
import { Carousel } from '@itclabs/react-ui/carousel';

const items = [
  { id: 'first', title: 'Lorem ipsum' },
  { id: 'second', title: 'Dolor sit amet' },
  { id: 'third', title: 'Consectetur adipiscing' },
  { id: 'fourth', title: 'Sed do eiusmod' },
];

export function ItemsExample() {
  const [index, setIndex] = useState(0);

  return (
    <Carousel
      aria-label="Featured items"
      items={items}
      getItemKey={(item) => item.id}
      renderItem={(item) => (
        <div className="rounded-panel border border-line bg-surface p-6 text-ink">
          {item.title}
        </div>
      )}
      perView={{ base: 1, sm: 2, lg: 3 }}
      index={index}
      onSlideChange={setIndex}
      dots
    />
  );
}
```

Labeled arrows and dots complement drag gestures and keyboard arrows. Non-looping edges disable the corresponding arrow. Autoplay is opt-in through `autoplay` or an options object such as `autoplay={{ delay: 5000 }}` and includes a pause/play control. Reduced motion removes scrolling animation and disables autoplay. Set `autoplay.force` only when automatic rotation should continue despite that preference.

See [Carousel stories](?path=/docs/modules-carousel--docs) for multi-row, hero, autoplay, and drag-free examples. These components accept `className`, typed `classNames` slots, refs, and `data-testid`; see [Customization](?path=/docs/guides-customization--docs).

## MediaGallery and Lightbox

Import both from `@itclabs/react-ui/media-gallery`. Supply `items` with stable `id`, `src`, and meaningful `alt` text; images can include dimensions for the host image adapter. Video items use `type: 'video'`, with optional `poster` and `thumbnail` URLs. Native video controls handle playback; leaving a video pauses it.

`index` and `onIndexChange` control zero-based item selection; use `defaultIndex` for uncontrolled selection. Indices are clamped to available items. Omit `thumbnails` for left placement on desktop and bottom placement on small screens, or set it to `left`, `bottom`, or `none`. `aspectRatio` controls the main viewport. Image hover zoom is enabled for fine mouse pointers and respects reduced motion; use `zoom` and `zoomScale` to configure it.

By default, activating an image opens the built-in fullscreen Lightbox. The example below uses `lightbox={false}` and `onOpen` to control a separate Lightbox, sharing selection with the gallery. A separate button also opens the viewer for the selected image or video. Replace the asset URLs with your own files.

```tsx
import { useState } from 'react';
import { Button } from '@itclabs/react-ui';
import {
  Lightbox,
  MediaGallery,
  type MediaItem,
} from '@itclabs/react-ui/media-gallery';

const items: MediaItem[] = [
  {
    id: 'front',
    src: '/media/front.jpg',
    alt: 'Front view',
    width: 800,
    height: 1000,
  },
  {
    id: 'detail',
    src: '/media/detail.jpg',
    alt: 'Fabric detail',
    width: 800,
    height: 1000,
  },
  {
    id: 'video',
    type: 'video',
    src: '/media/preview.mp4',
    alt: 'Rotating view',
    poster: '/media/preview.jpg',
    thumbnail: '/media/preview.jpg',
  },
];

export function MediaExample() {
  const [index, setIndex] = useState(0);
  const [open, setOpen] = useState(false);

  return (
    <div className="grid max-w-2xl gap-4">
      <MediaGallery
        aria-label="Item media"
        items={items}
        index={index}
        onIndexChange={setIndex}
        aspectRatio="4 / 5"
        lightbox={false}
        onOpen={(next) => {
          setIndex(next);
          setOpen(true);
        }}
      />
      <Button onClick={() => setOpen(true)}>Open fullscreen viewer</Button>
      <Lightbox
        items={items}
        open={open}
        onOpenChange={setOpen}
        index={index}
        onIndexChange={setIndex}
      />
    </div>
  );
}
```

Gallery arrow controls, keyboard arrows, and thumbnails complement swipe gestures. In Lightbox, Left/Right keys, navigation buttons, and thumbnails change items. Zoom buttons and double-click magnify images; drag to pan. Escape closes the dialog and restores focus to the opener. `open`/`onOpenChange` control visibility; `defaultOpen` initializes an uncontrolled viewer. Reduced motion removes overlay animation. Both components expose refs, `data-testid`, `className`, and typed `classNames` slots, including media, video, and thumbnails; Lightbox also exposes overlay, close, and zoom button slots.

See [MediaGallery stories](?path=/docs/modules-mediagallery--docs) and [Lightbox stories](?path=/docs/modules-lightbox--docs).

## Editing and displaying rich text

Import Editor from `/editor` and RichTextView from `/rich-text-view`. Both use the same content typography from the kit styles. Store HTML through `value` and `onValueChange`; RichTextView sanitizes it with a restricted Editor tag allowlist.

```tsx
import { useState } from 'react';
import { Editor } from '@itclabs/react-ui/editor';
import { RichTextView } from '@itclabs/react-ui/rich-text-view';

export function RichTextExample() {
  const [html, setHtml] = useState('<p>Lorem ipsum dolor sit amet.</p>');

  return (
    <div className="grid gap-6 md:grid-cols-2">
      <Editor label="Content" value={html} onValueChange={setHtml} />
      <RichTextView html={html} as="article" aria-label="Preview" />
    </div>
  );
}
```

The Editor link popover accepts absolute http, https, and mailto URLs. Enter applies the link; Escape dismisses the popover and returns focus to the editor. Code block and horizontal rule controls complement the formatting toolbar.

RichTextView accepts `as="div"` (default) or `as="article"`, `emptyFallback`, native props and ref, `data-testid`, `className`, and `classNames.root`. With default `sanitize={true}`, content is sanitized in a client effect: SSR and the first hydration render show the fallback, with no hydration mismatch. For SEO, sanitize on the server and pass `sanitize={false}`. This bypasses all sanitization: the host must guarantee the HTML is trusted and sanitized. Empty or fully stripped HTML uses the fallback.

See [Editor](?path=/docs/modules-editor--docs) and [RichTextView](?path=/docs/modules-richtextview--docs) for live preview and sanitization examples.
