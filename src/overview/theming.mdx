# Theming

Colors, fonts, radii, control sizes, shadows, and motion are CSS variables. Override tokens to change the appearance across components. Use [Customization](?path=/docs/guides-customization--docs) for individual controls and [Icons](?path=/docs/guides-icons--docs) for glyph configuration.

## Built-in presets

Import presets from **`@itclabs/react-ui/theme/presets`**. They are opt-in token objects with no runtime dependency; presets are not re-exported from the root or the general theme entry. Each named preset supplies `light` and `dark` palettes, while leaving font, radius, motion and layout tokens unchanged.

| Export        | Palette                                          |
| ------------- | ------------------------------------------------ |
| `forestTheme` | Muted green, following the kit's original brand. |
| `oceanTheme`  | Blue.                                            |
| `violetTheme` | Violet.                                          |
| `slateTheme`  | Blue-gray.                                       |
| `emberTheme`  | Earthy orange.                                   |

Use one named preset when the application has a fixed brand:

```tsx
'use client';

import { useState } from 'react';
import { Button, UIProvider, ThemeToggle, type ThemeMode } from '@itclabs/react-ui';
import { emberTheme } from '@itclabs/react-ui/theme/presets';

export function OrangeWorkspace() {
  const [mode, setMode] = useState<ThemeMode>('light');

  return (
    <UIProvider theme={emberTheme[mode]}>
      <ThemeToggle value={mode} onValueChange={setMode} appearance="switch" />
      <Button>Save</Button>
    </UIProvider>
  );
}
```

Mount the provider once at the client composition root. Pass the same mode to the preset and ThemeToggle; the host owns persistence and the initial SSR value. The token rule includes portals. Do not mount providers with different token palettes side by side: token themes apply to the document root. If host CSS has more-specific selectors on `html`, remove conflicting palette overrides or choose one source of truth.

For a host-controlled theme picker, import `themePresets`, `ThemePresetName` and `ThemePresetMode` from the same entry and use `themePresets[name][mode]`. This deliberately includes all five palettes. Override individual tokens by passing `defineTheme({ ...emberTheme.light, tokens: { ...emberTheme.light.tokens, 'radius-control': '1rem' } })`.

## Replace the font

Omit `fonts.css`, load your application's font, and override `--font-sans`:

```css
@layer theme, base, toastify, components, utilities;
@import 'tailwindcss';
@import '@itclabs/react-ui/theme/tokens.css';
@import '@itclabs/react-ui/theme/base.css';
@import '@itclabs/react-ui/theme/vendor.css';
@import '@itclabs/react-ui/theme/motion.css';

:root {
  --font-sans: Arial, system-ui, sans-serif;
}
```

Check the scripts your application supports at 12–14px and weights 500–700 before choosing a font. You can also set `font-sans` through `UIProvider theme.tokens`; the application must still load the font. Global CSS variables also reach dialogs, menus, and toasts portaled to `body`.

## Create a theme with CSS

```css
[data-theme='ocean'] {
  --color-brand-50: #eaf3f8;
  --color-brand-100: #d3e7f2;
  --color-brand-500: #3c83a7;
  --color-brand-700: #245b79;
  --color-brand-800: #1c4962;
  --radius-control: 0.375rem;
}
```

Place `data-theme` or the theme class on `<html>`. Interaction roles are resolved at the root, and overlays can portal outside an inner wrapper. Check WCAG AA contrast for the new palette. Use the Storybook **Theme** toolbar menu to preview themes.

## Set tokens through UIProvider

Use `theme.tokens` for runtime branding. CSS is the default choice for fixed branding. `defineTheme` validates and freezes the configuration; `UIProvider` also validates tokens passed as a plain object.

```tsx
import { Button, defineTheme, UIProvider } from '@itclabs/react-ui';

const theme = defineTheme({
  tokens: {
    'color-brand-700': '#1d4ed8',
    'radius-control': '1rem',
    'font-sans': 'Georgia, serif',
  },
});

export function Example() {
  return (
    <UIProvider theme={theme}>
      <Button>Save changes</Button>
    </UIProvider>
  );
}
```

Token names omit `--` and are typed by `UIThemeTokenName` / `UIThemeTokens`. Values must be nonempty CSS strings. Unknown names and values containing semicolons, braces, angle brackets, backslashes, line breaks, `/*`, or `!important` are rejected. Validation does not check CSS syntax or contrast.

The first provider with active tokens renders an ordinary inline `<style>` before its children. Its deterministic `:root` rule has no cascade layer, `href`, or `precedence`. Server rendering includes the rule without an effect. Updating tokens changes the style text while preserving child state; removing tokens or unmounting their owner removes the style. Token strings can cross a Server Component boundary; icon components must be configured in a client module.

Tokens apply to the whole page, including portals to `body`. Descendant providers inherit active tokens; their own token overrides are ignored, with one warning per provider in development. Icons and locale settings still compose. Use CSS selectors on `<html>` to switch themes. `useTheme()` exposes read-only `tokens`; `colors` remains a set of CSS `var()` references.

The unlayered provider rule wins over defaults in `@layer theme`. For unlayered application CSS, specificity wins first, then source order at equal specificity. For example, `html[data-theme]` is more specific than `:root`. Choose one override source per token to keep the cascade predictable.

## Complete CSS reference

`@itclabs/react-ui/theme/custom-theme.example.css` lists every public token with its default value. Copy it into your application, keep the overrides you need, and import them after the kit CSS. There is no need to load the unchanged reference file at runtime.

To switch themes by selector, replace `:root` with `[data-theme='name']` on `<html>`. This covers portals and recalculates derived roles and shadows. Check WCAG AA contrast for text/background pairs and control borders. Reserve `line` for decoration and `control-border` for controls.

## Appearance control

ThemeToggle provides icon, button and switch appearances. Keep the chosen mode in host state; apply your own CSS palette to the document root so portalled overlays follow. Persistence and system preferences remain host decisions. The control does not change document attributes itself.

```tsx
import { useEffect, useState } from 'react';
import { ThemeToggle, type ThemeMode } from '@itclabs/react-ui';

export function AppearanceSettings() {
  const [mode, setMode] = useState<ThemeMode>('light');
  useEffect(() => {
    const previous = document.documentElement.dataset.colorMode;
    document.documentElement.dataset.colorMode = mode;

    return () => {
      if (previous === undefined) delete document.documentElement.dataset.colorMode;
      else document.documentElement.dataset.colorMode = previous;
    };
  }, [mode]);

  return <ThemeToggle value={mode} onValueChange={setMode} appearance="switch" />;
}
```

Define your dark CSS token overrides under `[data-color-mode='dark']`. See the ThemeToggle Playground for a working sample palette.
