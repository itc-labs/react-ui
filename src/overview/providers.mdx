# Providers & adapters

`UIProvider` configures theme, language, host routing, and image rendering. Nested `UIProvider` scopes provide adapter overrides. `ToastProvider` and `ModalProvider` mount imperative feedback services. The application owns data fetching and business behavior.

Without configuration, controls use the `vi-VN` locale, outline icons, CSS tokens, and native links and images. Toast and modal APIs require mounted providers.

## UIProvider props

All configuration props are optional; `children` is required. Adapter types are exported from `@itclabs/react-ui`. Theme types are exported from `@itclabs/react-ui/theme`; locale types from `@itclabs/react-ui/i18n`.

| Prop              | Type                  | Behavior                                                                                                                                                                                                    |
| ----------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `link`            | `UiLinkComponent`     | Host link adapter; inherits when omitted, defaulting to native links.                                                                                                                                       |
| `image`           | `UiImageComponent`    | Host image adapter; inherits when omitted, defaulting to native images.                                                                                                                                     |
| `theme`           | `UITheme`             | Optional readonly `icons` and `tokens` settings; inherits the parent theme.                                                                                                                                 |
| `locale`          | `string \| UILocale`  | A locale code or an object containing `code`, readonly `messages`, and optional `calendarLocale`. Inherits the parent; defaults to `vi-VN`.                                                                 |
| `translations`    | `UITranslations`      | A readonly array of `{ locale: string; messages: Readonly<Partial<UIMessages>> }`. Replaces the inherited catalog when supplied. Defaults to an empty catalog with built-in English and Vietnamese support. |
| `fallbackLocale`  | `string`              | Fallback locale code for catalog resolution; inherits the parent, defaulting to `en-US`.                                                                                                                    |
| `messages`        | `Partial<UIMessages>` | Message overrides for this subtree. Values are strings or plural forms with required `other` and optional `Intl.LDMLPluralRule` keys.                                                                       |
| `calendarLocales` | `UICalendarLocales`   | A readonly record mapping locale codes to `NonNullable<UILocale['calendarLocale']>` (React Day Picker locale objects). Merges with the parent map; defaults to an empty map.                                |
| `children`        | `ReactNode`           | Application content.                                                                                                                                                                                        |

`UITheme.tokens` is `Readonly<UIThemeTokens>`: typed CSS token names without the `--` prefix and CSS string values. Empty values, unknown names, and unsafe declaration syntax are rejected. `UITheme.icons` accepts `packs`, `defaultPack`, `variant` (`outline` or `bold`), `overrides`, `size`, and `strokeWidth`. Only the kit's internal glyphs ship in its default registry; import individual glyphs or register a catalog for additional icons. See [Theming](?path=/docs/guides-theming--docs) and [Icons](?path=/docs/guides-icons--docs).

String locales resolve against the catalog, then the configured fallback, then English. Missing message keys fall back through the selected built-in locale and fallback catalog. A `UILocale` object is used directly. See [Localization](?path=/docs/guides-localization--docs) for catalogs and calendar locale setup.

## Provider order and mounting

Use this order at the application root. Each example below is a separate complete client module.

```tsx
'use client';

import type { ReactNode } from 'react';
import {
  UIProvider,
  ToastProvider,
  ModalProvider,
  type UiLinkProps,
  type UiImageProps,
} from '@itclabs/react-ui';

function AppLink(props: UiLinkProps) {
  return <a {...props} />;
}

function AppImage(props: UiImageProps) {
  return <img {...props} />;
}

export function UIRoot({ children }: { children: ReactNode }) {
  return (
    <UIProvider locale="en-US" link={AppLink} image={AppImage}>
      <ToastProvider position="bottom-right">
        <ModalProvider>{children}</ModalProvider>
      </ToastProvider>
    </UIProvider>
  );
}
```

- Put `UIProvider` outside feedback providers so their labels and icons use its configuration.
- Configure `UIProvider link` and `image` for consumers such as Breadcrumb, Sidebar, menu links, avatars, and file previews.
- Mount one default `ToastProvider` and one default `ModalProvider` for the exported `toast` and `modal` clients. They do not depend on each other's controllers; either can wrap the other. Keep both around children that use their hooks.
- Call imperative APIs after mount, for example in event handlers. There is no server or pre-mount queue. `useToast()` and `useModal()` require their respective providers.

`ToastProvider` supports `position`, `duration` (milliseconds or `false`), `maxVisible`, `pauseOnHover`, `pauseOnFocusLoss`, `newestOnTop`, `closeLabel`, `viewportLabel`, `client`, `className`, `classNames`, and `data-testid`. Defaults include bottom-right positioning, a 5000 ms duration, and five visible messages.

`ModalProvider` supports `client`, `className`, `classNames`, and `data-testid`. Use imperative modals for short confirmations and alerts. Use a declarative `Dialog` for longer forms with local state. See [Overlays & feedback](?path=/docs/guides-overlays-feedback--docs).

## Nesting and scope

**Theme:** icon settings inherit; nested `packs` and `overrides` merge by key. The first provider supplying nonempty tokens owns a document-wide, unlayered `:root` style, rendered before its children, including during SSR. It updates and disappears with that provider. Descendant token overrides are ignored when an ancestor already owns tokens, with a development warning. Tokens cover portalled overlays; nested providers do not create a local token scope. Use a selector on the document root to switch themes, and avoid competing CSS and provider overrides for the same token.

**Locale:** nested providers inherit omitted settings. Calendar maps merge, while a supplied translations array replaces the catalog. Message overrides merge for the same locale; switching locale code or supplying a different locale object resets inherited overrides. These settings apply to the React subtree.

**Adapters:** a nested `UIProvider` replaces only the adapters supplied through `link` and `image`; each omitted adapter inherits from its parent. Use `<UIProvider link={ScopedLink}>` to override only links in a subtree while retaining the parent image adapter.

**Feedback:** each toast or modal provider has its own controller. One client can bind to only one mounted provider. Use `createToastClient()` and `createModalClient()` for independent application roots, and retain those clients for the root's lifetime. For a local subtree, set `client={null}` and call `useToast()` or `useModal()`; the default exported clients still target the root providers. Changing a modal provider's client or unmounting it settles pending modals as dismissed.

## SSR and client boundaries

In Next.js App Router, put providers, hooks, and adapters in a `'use client'` module and render that wrapper from the server layout. Server-rendered content can be passed as `children`.

Do not pass adapter functions or icon components from a Server Component across the client boundary. Define or import them in the client module. Token strings and JSON translation catalogs are serializable. Calendar locale objects contain functions, so import them on the client as well. Keep the server's initial locale and theme consistent with the client's initial render.

## Next.js App Router adapters

In a Next.js host with `next` installed, use `next/link` and `next/image`. The image adapter falls back to a native image when either dimension is missing, because this recipe uses explicit dimensions for optimized images. Both branches preserve native attributes, events, refs, and `data-testid`.

```tsx
'use client';

import type { ReactNode } from 'react';
import NextLink from 'next/link';
import NextImage from 'next/image';
import {
  UIProvider,
  ToastProvider,
  ModalProvider,
  type UiLinkProps,
  type UiImageProps,
} from '@itclabs/react-ui';

function AppLink(props: UiLinkProps) {
  return <NextLink {...props} />;
}

function AppImage({ width, height, ...props }: UiImageProps) {
  if (width === undefined || height === undefined) {
    return <img {...props} width={width} height={height} />;
  }

  return <NextImage {...props} width={width} height={height} />;
}

export function AppProviders({ children }: { children: ReactNode }) {
  return (
    <UIProvider locale="en-US" link={AppLink} image={AppImage}>
      <ToastProvider>
        <ModalProvider>{children}</ModalProvider>
      </ToastProvider>
    </UIProvider>
  );
}
```

Render `AppProviders` around the layout's children inside the document body. Supply positive image dimensions when requesting optimization and configure allowed remote image sources in the host's Next.js configuration.

## React Router link adapter

React Router's `Link` takes `to` instead of `href`. This complete module accepts the host's router component as a prop, keeping the kit independent of the router package. Pass the `Link` exported by your installed `react-router` or `react-router-dom` package as `RouterLink`, and render this wrapper **inside** your router. Native image rendering continues to inherit from the surrounding provider.

```tsx
'use client';

import { useMemo, type ComponentType, type ReactNode } from 'react';
import { UIProvider, type UiLinkProps } from '@itclabs/react-ui';

type RouterLinkProps = Omit<UiLinkProps, 'href'> & { to: string };

export function RouterAdapters({
  RouterLink,
  children,
}: {
  RouterLink: ComponentType<RouterLinkProps>;
  children: ReactNode;
}) {
  const AppLink = useMemo(() => {
    function Adapter({ href, ...props }: UiLinkProps) {
      return <RouterLink {...props} to={href} />;
    }

    return Adapter;
  }, [RouterLink]);

  return <UIProvider link={AppLink}>{children}</UIProvider>;
}
```

Keep the adapter's identity stable to avoid remounting links. Use the same provider configuration in tests and stories as in the host application, adding only the feedback providers a test needs.
