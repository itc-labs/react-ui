Ứng dụng chịu trách nhiệm tải dữ liệu; UI kit nhận dữ liệu và callback qua props.

## Thứ tự lồng

```tsx snippet
'use client';

import NextLink from 'next/link';
import NextImage from 'next/image';
import {
  UIProvider,
  LinkImageProvider,
  ToastProvider,
  ModalProvider,
} from '@itclabs/react-ui';

export function UIRoot({ children }: { children: React.ReactNode }) {
  return (
    <UIProvider locale="vi-VN">
      <LinkImageProvider Link={AppLink} Image={AppImage}>
        <ToastProvider position="bottom-right">
          <ModalProvider>{children}</ModalProvider>
        </ToastProvider>
      </LinkImageProvider>
    </UIProvider>
  );
}
```

1. **UIProvider ngoài cùng**: ToastProvider, ModalProvider và mọi component đọc nhãn mặc định từ locale của nó.
2. **LinkImageProvider**: Breadcrumb, Sidebar, DropdownMenu (item có `href`), Avatar và file preview dùng adapter này.
3. **ToastProvider**: chỉ mount **một** provider gốc để `toast.success/error/...` hoạt động ở mọi nơi, kể cả code không phải React.

4. **ModalProvider**: cùng tầng provider ứng dụng với ToastProvider, bên trong UIProvider và LinkImageProvider. Cả hai bọc children để dùng hook; không phụ thuộc controller của nhau. Chỉ mount một provider gốc cho facade `modal`.

Dùng modal imperative cho confirm/alert ngắn và code không phải React. Dùng `<Dialog>` khai báo cho form và nội dung dài có state cục bộ. Xem **Components/Modal** và `docs/UI_MODAL.md`.

## Token giao diện qua UIProvider

`theme.tokens` nhận các chuỗi CSS có tên typed, không có tiền tố `--`; có thể dùng `defineTheme({ tokens: { 'color-brand-700': '#1d4ed8' } })`. Tên lạ, giá trị rỗng và ký tự có thể thoát declaration/style bị từ chối. Xem **Overview/Theming** để biết đầy đủ quy tắc validation và file CSS tham khảo.

Provider ngoài cùng có token render `<style>` inline trước children, với rule `:root` không layer. SSR chứa rule ngay; style cập nhật và bị gỡ cùng provider. Rule thắng layer theme mặc định; CSS host không layer còn theo specificity và thứ tự xuất hiện. Chọn CSS hoặc UIProvider cho cùng token để tránh xung đột. Token là toàn trang, bao phủ portal; provider con không tạo scope token riêng.

## Server Components (Next.js App Router)

- Đặt các provider trong một file `'use client'` (composition root), rồi dùng trong `layout.tsx`.
- Không truyền component/hàm (adapter, icon pack) từ Server Component sang Client Component qua props; định nghĩa chúng ngay trong file client đó.
- `theme.tokens` là chuỗi serializable, có thể truyền từ Server Component; `useTheme().tokens` trả cấu hình đang hoạt động chỉ đọc.
- `translations` dạng JSON truyền được qua ranh giới server/client; `calendarLocales` là hàm nên khai báo phía client.
- Không có hàng đợi toast/modal phía server hoặc trước mount: chỉ gọi facade trong trình duyệt sau khi provider mount.

## Adapter link và ảnh

```tsx snippet
function AppLink(props: UiLinkProps) {
  return <NextLink {...props} />;
}

function AppImage({ width, height, ...props }: UiImageProps) {
  // next/image cần kích thước; thiếu thì dùng img native.
  if (!width || !height) return <img {...props} />;

  return <NextImage {...props} width={width} height={height} />;
}
```

Với React Router, map `href` sang `to`: `<RouterLink {...props} to={props.href} />`. Adapter nhận đủ thuộc tính native, ref, sự kiện và `data-testid`.

## Lồng theo phạm vi

- `UIProvider` con bỏ qua `theme.tokens` riêng nếu cha đã có token và cảnh báo một lần trong development; dùng selector CSS trên `<html>` để đổi theme. Provider lồng nhau vẫn gộp icon pack/override của cha; `locale`/`messages` của con áp dụng cho nhánh con.
- `LinkImageProvider` lồng nhau chỉ thay adapter được truyền, adapter còn lại kế thừa từ cha.
- Ứng dụng độc lập trên cùng trang dùng `createToastClient()` và truyền `client` cho `ToastProvider` riêng; `client={null}` khi chỉ dùng `useToast()` trong một nhánh.

- Modal dùng `createModalClient()` cho ứng dụng độc lập và `client={null}` với `useModal()` cho phạm vi cục bộ. Đổi client hoặc unmount giải quyết mọi modal như bị hủy.
