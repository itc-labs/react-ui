# Navigation

The host owns routing, the current path, and authorization. The kit receives these
through props; it does not read sessions or import a router. Keep framework
integration in the host application. See [Navbar](?path=/docs/modules-navbar--docs),
[Sidebar](?path=/docs/modules-sidebar--docs), and
[TopLoader](?path=/docs/components-toploader--docs) for interactive API examples.
For provider setup, see [Providers & adapters](?path=/docs/guides-providers-adapters--docs).

## Sidebar and application layout

`Sidebar.header` accepts `{ logo, title, subtitle, href }` or a React node such as a
workspace switcher; the collapse toggle sits in the same row. Use `UserMenu` in
`footer` (give its trigger `w-full` to span the sidebar). Item `badge` accepts a
number, shown as a quiet count, or Badge props without `children` when the count
needs a tone such as `danger`; both become a dot in the collapsed rail.
Control collapse with `collapsed` and `onCollapsedChange`, or initialize it with
`defaultCollapsed`. The `toggleShortcut="mod+b"` shortcut is opt-in.

The rail keeps label tooltips and opens submenus as side flyouts. Below `lg`, a
menu button opens a Drawer with the same permission-filtered tree and active path.
`WorkspaceShell` adjusts its columns from the Sidebar's `data-collapsed` attribute;
pass Sidebar directly to its `sidebar` slot. `variant="inset"` (default) raises the
header and page into a rounded card beside the sidebar; `variant="classic"` keeps a
flat page divided from the sidebar by a rule. The sidebar width comes from the
`--container-sidebar` token (15rem).

Try [Collapsible](?path=/story/modules-sidebar--collapsible),
[CollapsedFlyout](?path=/story/modules-sidebar--collapsed-flyout), and
[Mobile](?path=/story/modules-sidebar--mobile) below `lg`.
[ApplicationLayout](?path=/story/templates-applicationlayout--playground) is a
clickable application demo; [TopNavigationLayout](?path=/story/templates-applicationlayout--top-navigation-layout)
combines a Navbar mega menu, underline indicator, and UserMenu. These demos use
host state and a UiLink adapter without a framework dependency.

## One shared menu

Define the menu once in a host module such as `navigation.ts`. Extend `NavItem`
with labels and grouping, then map it to `NavbarItem` and `SidebarEntry`.
Preserve `id`, `href`, `exact`, and `access`. Keep IDs stable and unique among
siblings, including sections; do not derive them from translated labels or positions.

```tsx
// navigation.ts — host-owned data, no framework imports.
import type { NavItem, NavbarItem, SidebarEntry } from '@itclabs/react-ui';

type Permission = 'profile:read' | 'team:read';
type MenuBase = Omit<NavItem<Permission>, 'items' | 'children'>;
type MenuLink = MenuBase & {
  kind: 'link';
  label: string;
  href: string;
};
type MenuSection = {
  id: string;
  title: string;
  items: readonly MenuLink[];
};
type MenuItem =
  | MenuLink
  | (MenuBase & {
      kind: 'group';
      label: string;
      items: readonly MenuLink[];
    })
  | (MenuBase & {
      kind: 'mega';
      label: string;
      sections: readonly MenuSection[];
    });

export const menu: readonly MenuItem[] = [
  { kind: 'link', id: 'home', label: 'Home', href: '/', exact: true },
  {
    kind: 'group',
    id: 'settings',
    label: 'Settings',
    items: [
      {
        kind: 'link',
        id: 'profile',
        label: 'Profile',
        href: '/settings/profile',
        access: 'profile:read',
      },
      {
        kind: 'link',
        id: 'team',
        label: 'Team',
        href: '/settings/team',
        access: 'team:read',
      },
    ],
  },
  {
    kind: 'mega',
    id: 'resources',
    label: 'Resources',
    sections: [
      {
        id: 'guides',
        title: 'Guides',
        items: [
          {
            kind: 'link',
            id: 'start',
            label: 'Getting started',
            href: '/guides/start',
          },
        ],
      },
      {
        id: 'support',
        title: 'Support',
        items: [{ kind: 'link', id: 'help', label: 'Help', href: '/help' }],
      },
    ],
  },
];

export const navbarItems: NavbarItem<Permission>[] = menu.map((item) => {
  switch (item.kind) {
    case 'group':
      return { ...item, type: 'dropdown', children: item.items };
    case 'mega':
      return { ...item, type: 'mega' };
    case 'link':
      return { ...item, type: 'link' };
  }
});

export const sidebarItems: SidebarEntry<Permission>[] = menu.map((item) => {
  switch (item.kind) {
    case 'group':
      return { ...item, type: 'group' };
    case 'mega':
      return {
        ...item,
        type: 'submenu',
        items: item.sections.map((section) => ({
          id: section.id,
          type: 'group',
          label: section.title,
          items: section.items,
        })),
      };
    case 'link':
      return { ...item, type: 'item' };
  }
});
```

Navbar renders groups as dropdowns and preserves mega-menu sections. Sidebar
renders labeled groups and submenus from the same data. Both filter permissions
before resolving active state and remove empty groups and sections. Without a
`canAccess` callback, access is unrestricted.

## Next.js App Router: client root

Mount this client root in a persistent layout, using `UIProvider` for the host adapters.
After verifying the session, the server supplies permissions as a serializable
array. Import menu data and define adapters in the client module so functions do
not cross the server/client boundary.

This complete module accepts `items` and `pathname` as props. In the host's client
wrapper, import `navbarItems` from your menu module and pass
`pathname={usePathname() ?? ''}` using `usePathname` from `next/navigation`.
See [usePathname](https://nextjs.org/docs/app/api-reference/functions/use-pathname).

```tsx
'use client';

import type { ReactNode } from 'react';
import NextLink from 'next/link';
import {
  UIProvider,
  Navbar,
  TopLoaderProvider,
  type NavbarItem,
  type UiLinkProps,
} from '@itclabs/react-ui';

function AppLink(props: UiLinkProps) {
  return <NextLink {...props} />;
}

export function NavigationRoot({
  children,
  items,
  pathname,
  permissions,
}: {
  children: ReactNode;
  items: readonly NavbarItem<string>[];
  pathname: string;
  permissions: readonly string[];
}) {
  return (
    <UIProvider link={AppLink}>
      <TopLoaderProvider trackLinks currentPath={pathname}>
        <Navbar
          brand="Lorem ipsum"
          brandHref="/"
          items={items}
          currentPath={pathname}
          canAccess={(access) => permissions.includes(access)}
          data-testid="primary-navbar"
        />
        {children}
      </TopLoaderProvider>
    </UIProvider>
  );
}
```

To add Sidebar, import `Sidebar` and `sidebarItems` in that client module, then pass
`items={sidebarItems}`, `currentPath={pathname}`, and the same permission callback.
If no ancestor supplies an image adapter, omitting `image` keeps native images;
otherwise the adapter inherits from the nearest adapter provider.

For query-only navigation, combine pathname with `useSearchParams()` for
TopLoaderProvider's `currentPath`; keep Navbar's path as the pathname. Follow the
host framework's Suspense requirements.

## React Router: equivalent root

Mount inside the host router, outside route elements that unmount on navigation.
Pass the host's `Link` as `RouterLink`, and pass `pathname` and `search` from
`useLocation()`. Both are exported by `react-router` in current versions.
The adapter maps `href` to `to` and forwards native attributes, events, React 19
refs, and `data-testid`. External and non-root-relative URLs keep native anchors.
Memoizing the adapter keeps its identity stable across route changes.

```tsx
'use client';

import { useMemo, type ComponentType, type ReactNode } from 'react';
import {
  UIProvider,
  Navbar,
  TopLoaderProvider,
  type NavbarItem,
  type UiLinkProps,
} from '@itclabs/react-ui';

type RouterLinkProps = Omit<UiLinkProps, 'href'> & { to: string };

export function NavigationRoot({
  children,
  RouterLink,
  items,
  pathname,
  search,
  permissions,
}: {
  children: ReactNode;
  RouterLink: ComponentType<RouterLinkProps>;
  items: readonly NavbarItem<string>[];
  pathname: string;
  search: string;
  permissions: readonly string[];
}) {
  const AppLink = useMemo(() => {
    function Adapter({ href, ...props }: UiLinkProps) {
      if (!href.startsWith('/') || href.startsWith('//')) {
        return <a {...props} href={href} />;
      }

      return <RouterLink {...props} to={href} />;
    }

    return Adapter;
  }, [RouterLink]);

  return (
    <UIProvider link={AppLink}>
      <TopLoaderProvider trackLinks currentPath={pathname + search}>
        <Navbar
          brand="Lorem ipsum"
          brandHref="/"
          items={items}
          currentPath={pathname}
          canAccess={(access) => permissions.includes(access)}
          data-testid="primary-navbar"
        />
        {children}
      </TopLoaderProvider>
    </UIProvider>
  );
}
```

Pass `navbarItems` from the shared menu as `items`. Sidebar uses `sidebarItems`
with the same pathname and permission callback.
See [React Router Link](https://reactrouter.com/api/components/Link).

## Menu filtering and route protection

**Hiding a menu item is not security.** Users can enter a URL or call an API
directly. `canAccess` controls presentation. The host must verify sessions and
permissions on the server when reading data and performing actions.

This Next.js 15 `middleware.ts` recipe calls the host's `verifySession` function,
which must validate the session rather than trust an unverified cookie. It should
return a session with a `permissions` array, or no session. On Next.js 16+, rename
the file to `proxy.ts` and the exported function to `proxy`; see the
[Proxy documentation](https://nextjs.org/docs/app/api-reference/file-conventions/proxy).

```ts
// middleware.ts — host application, Next.js 15.
import { NextResponse, type NextRequest } from 'next/server';
import { verifySession } from './auth/session';

export async function middleware(request: NextRequest) {
  const session = await verifySession(request);
  if (!session) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  const required = request.nextUrl.pathname.startsWith('/settings/team')
    ? 'team:read'
    : 'profile:read';
  if (!session.permissions.includes(required)) {
    return NextResponse.redirect(new URL('/forbidden', request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ['/settings/profile/:path*', '/settings/team/:path*'],
};
```

The matcher covers only the routes in this example. Check permissions again in
Server Components, route handlers, and the data access layer; middleware/proxy
does not replace those checks. A React Router loader can redirect before rendering,
but the API/server must still authenticate and authorize requests independently.

## Programmatic navigation and data loading

`trackLinks` observes eligible same-origin HTTP(S) anchor clicks and completes
progress when `currentPath` changes. It ignores modified clicks, downloads,
non-self targets, external URLs, the current URL, and hash-only changes.
Programmatic navigation and browser back/forward require a manual `start()`.

Next.js `router.push()` does not return a route-completion promise. Let the provider
finish when the path changes. Call `done()` for errors, cancellations, or redirects
back to the same URL; do not call it immediately after a successful `push()`.

This complete module accepts the current pathname and the host router. In a Next.js
client wrapper, pass `pathname={usePathname() ?? ''}` and `router={useRouter()}`
using hooks from `next/navigation`.

```tsx
'use client';

import { Button, topLoader } from '@itclabs/react-ui';

export function OpenProfile({
  pathname,
  router,
}: {
  pathname: string;
  router: { push: (href: string) => void };
}) {
  function openProfile() {
    if (pathname === '/settings/profile') return;

    topLoader.start();
    try {
      router.push('/settings/profile');
    } catch (error) {
      topLoader.done();
      throw error;
    }
  }

  return <Button onClick={openProfile}>Open profile</Button>;
}
```

Call the facade only after its provider mounts. Inside components,
`useTopLoader()` returns the nearest provider's controller. Render this refresh
control below `TopLoaderProvider` and pass the host's data-loading callback; the
`finally` block completes progress even if loading fails:

```tsx
'use client';

import { Button, useTopLoader } from '@itclabs/react-ui';

export function Refresh({ loadData }: { loadData: () => Promise<unknown> }) {
  const loader = useTopLoader();

  async function refresh() {
    loader.start();
    try {
      await loadData(); // Host can pass () => fetch('/api/profile').
    } finally {
      loader.done();
    }
  }

  return <Button onClick={refresh}>Refresh</Button>;
}
```

The controller methods share one activity rather than counting requests. For
concurrent tasks, call `done()` only after all tasks finish. Canceled clicks and
route errors also need `done()`; anchor events cannot reveal their outcome.

## Active matching rules

| Rule               | Result                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Segment boundaries | `/admin` matches `/admin/users`, but not `/administrator`.                                                                                                                                              |
| Longest match wins | The longest matching normalized href wins; ties prefer the deeper item, then the first item.                                                                                                            |
| Root               | `/` matches only itself by default; set `exact: false` to allow prefix matching.                                                                                                                        |
| Overrides          | `exact` takes precedence over its `end` alias. `isActive(item, currentPath)` replaces path matching. An explicit `active` overrides the predicate; `active: true` takes priority over inferred matches. |
| Normalization      | Query strings, hashes, and trailing slashes are ignored. Matching is case-sensitive. External URLs and relative paths do not match.                                                                     |

Only the winning link receives `aria-current="page"`; its ancestors are marked as
the active branch. See the full contract in
[UI_NAVIGATION.md](https://github.com/itc-labs/react-ui/blob/main/docs/UI_NAVIGATION.md).

## Brand, switcher, and UserMenu

Navbar has a surface background, bottom border, and minimum height of 64px.
`brand` accepts a React node or `{ logo, title, subtitle, href }`.
`switcher` accepts controls such as segmented Tabs or Select and appears beside
the brand in the mobile Drawer. `activeIndicator` defaults to `underline`; use
`pill` for a selected background. The host supplies `currentPath` and permissions.

```tsx
import {
  Icon,
  IconButton,
  Navbar,
  Tabs,
  TabsList,
  TabsTrigger,
  UserMenu,
} from '@itclabs/react-ui';
import { HomeIcon } from '@itclabs/react-ui/icons/outline/home';
import { BellIcon } from '@itclabs/react-ui/icons/outline/bell';

export function NavigationBar() {
  return (
    <Navbar
      brand={{
        logo: <Icon glyph={HomeIcon} />,
        title: 'Lorem ipsum',
        subtitle: 'Dolor sit amet',
        href: '/',
      }}
      switcher={
        <Tabs defaultValue="personal" variant="segmented" size="sm">
          <TabsList aria-label="Workspace">
            <TabsTrigger value="personal">Personal</TabsTrigger>
            <TabsTrigger value="team">Team</TabsTrigger>
          </TabsList>
        </Tabs>
      }
      items={[{ id: 'home', label: 'Home', href: '/', icon: HomeIcon }]}
      currentPath="/"
      actions={
        <>
          <IconButton
            icon={BellIcon}
            label="Notifications"
            variant="secondary"
            badge={3}
          />
          <UserMenu
            name="Lorem Ipsum"
            description="Dolor sit amet"
            header={<span>user@example.com</span>}
            items={[{ id: 'profile', label: 'Profile', href: '/profile' }]}
          />
        </>
      }
    />
  );
}
```

UserMenu collapses to an avatar below `sm` by default. Set `compact` to always
collapse it, or `collapseOnMobile={false}` to keep the name visible at every size.
`items` accepts DropdownMenuEntry data; `header` accepts content such as a name or
email. See [Navbar](?path=/docs/modules-navbar--docs) and
[UserMenu](?path=/docs/modules-usermenu--docs) for states and `classNames` slots.

## PageHeader and Navbar

`Navbar` provides application-wide navigation. `PageHeader` provides the title
block for each page. The host supplies breadcrumbs explicitly; PageHeader does
not infer them from routes.

```tsx
import { Breadcrumb, PageHeader } from '@itclabs/react-ui';

export function ProfileHeading() {
  return (
    <PageHeader
      title="Profile"
      breadcrumb={
        <Breadcrumb
          items={[
            { key: 'home', title: 'Home', href: '/' },
            { key: 'settings', title: 'Settings', href: '/settings' },
            { key: 'current', title: 'Profile' },
          ]}
        />
      }
    />
  );
}
```
