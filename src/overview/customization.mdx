# Customization

Use `className` for the component's primary element and typed `classNames` slots for its parts. Use [Theming](?path=/docs/guides-theming--docs) for shared design tokens and [Icons](?path=/docs/guides-icons--docs) for icon packs. A single control does not need a new theme.

## Merge order and cn()

Components merge default and state classes first, then your slot classes, then `className` on the same element. The last conflicting utility wins through `cn()`, which combines `clsx` with Tailwind merging, including the kit's semantic typography, spacing, radius, and shadow utilities. This utility merging does not replace the CSS cascade for arbitrary custom classes.

The element receiving `className` varies by component. For `Input`, it is the native input; `classNames.root` styles the field wrapper. `rootClassName`, where supported, comes after the root slot.

```tsx
import { cn, Input } from '@itclabs/react-ui';

export function Example() {
  return (
    <Input
      label="Display name"
      hint="Enter the name shown on your profile."
      classNames={{
        root: 'max-w-sm gap-2',
        label: 'text-brand-700',
        control: 'rounded-full',
        hint: 'text-ui-sm',
      }}
      className={cn('px-4', 'px-6')}
    />
  );
}
```

Here `px-6` wins over `px-4`; the control slot replaces the default radius. Your application must provide CSS for its classes. With Tailwind, ensure your application's source files are scanned.

## Editor autocomplete

Install the [official Tailwind CSS IntelliSense extension](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss) in VS Code or a compatible editor. Install Tailwind CSS v4 in the consuming application's devDependencies and use a local `.css` entry that imports the kit source stylesheet:

```bash
pnpm add -D tailwindcss @tailwindcss/vite
```

Use `@tailwindcss/vite` for Vite; Next.js uses `@tailwindcss/postcss` with the corresponding PostCSS configuration instead. The kit does not install or configure the host's build plugin.

In the consuming application, for example `src/styles/app.css`:

```css
@import '@itclabs/react-ui/theme/styles.css';
```

Import that stylesheet once from the application's root. The kit's tokens become Tailwind utilities, so `bg-surface`, `text-ink` and `rounded-control` are available in both builds and suggestions. A plain `ui.css` import supplies precompiled kit styles; it does not generate host utilities or replace a Tailwind source entry for editor discovery.

Put the following in **the consuming workspace root's `.vscode/settings.json`**, not inside `node_modules` or the UI package. Merge it into existing settings. Replace `src/styles/app.css` with the actual CSS entry; paths are relative to the opened workspace:

```json
{
  "editor.quickSuggestions": {
    "strings": "on"
  },
  "tailwindCSS.classAttributes": ["class", "className", "classNames", "rootClassName"],
  "tailwindCSS.classFunctions": ["cn", "clsx", "cva"],
  "tailwindCSS.experimental.configFile": "src/styles/app.css"
}
```

`classAttributes` covers JSX class props; `classFunctions` enables completion inside `cn()`, `clsx()` and `cva()`. Nested object strings in `classNames` are not reliably recognized in every extension version. Wrap a slot value in `cn('...')` for a supported completion context, including callback returns:

```tsx
import { cn, Input } from '@itclabs/react-ui';

export function StyledField() {
  return (
    <Input
      label="Name"
      className="text-ink"
      classNames={{ root: cn('max-w-sm gap-2'), label: cn('text-muted text-ui-sm') }}
    />
  );
}
```

For a monorepo opened at its root, point the CSS entry to all consuming source folders:

```json
{
  "tailwindCSS.experimental.configFile": {
    "apps/web/src/styles/app.css": ["apps/web/src/**", "packages/module-*/src/**"]
  }
}
```

The kit registers its own `@source` paths. If host sources are outside Tailwind's automatic discovery, add their `@source` entries relative to the host stylesheet; editor glob mappings do not control generated CSS. Write complete literal classes such as `text-danger-700`; a constructed string such as `text-${tone}-700` cannot be detected statically.

To troubleshoot, open a TSX file in the mapped source folder, type `bg-` inside `cn('')`, and press Ctrl+Space. Try `text-ui-sm`, `h-control-sm` and `rounded-control`, then hover to inspect their token references. Run **Tailwind CSS: Show Output** to check stylesheet resolution. If that command is missing, check extension activation, the local Tailwind installation and the configured CSS path; use **Developer: Reload Window** after changing editor settings. Runtime `defineTheme` changes values of known tokens; it cannot teach the editor new utility names.

Settings are based on the [official extension documentation](https://github.com/tailwindlabs/tailwindcss-intellisense#readme). `experimental.configFile` is experimental. No editor automation was run to verify a particular editor version.

For optional class sorting with `prettier-plugin-tailwindcss`, set `tailwindStylesheet` to the same CSS entry, `tailwindAttributes` to include `classNames` and `tailwindFunctions` to include `cn`. Sorting is separate from IntelliSense. See the [plugin configuration](https://github.com/tailwindlabs/prettier-plugin-tailwindcss#readme).

## Select slots

Select exposes label, control, menu, option, and other React Select slots. React Select slot values accept strings or callbacks with state such as `isFocused`, `isSelected`, and `isDisabled`. `className` targets the React Select container; `classNames.root` targets the outer field wrapper.

```tsx
import { cn, Select } from '@itclabs/react-ui';

export function Example() {
  return (
    <Select
      label="Status"
      options={[
        { value: 'draft', label: 'Draft' },
        { value: 'published', label: 'Published' },
      ]}
      classNames={{
        root: 'max-w-sm',
        control: 'rounded-full',
        option: ({ isSelected }) => cn(isSelected && 'font-semibold'),
      }}
    />
  );
}
```

## Compound components and portals

Tabs, Breadcrumb, Sidebar, and Dialog parts accept their own `className`. `DialogContent` and `DrawerContent` also expose `classNames.overlay` and `classNames.close` for the parts they render internally. Menu and Popover retain Radix portals and semantics. See [Overlays & feedback](?path=/docs/guides-overlays-feedback--docs).

Other controls include a **CustomClasses** story in their component group. Single-element components such as Icon and Skeleton use `className`. Headless roots that render no DOM do not gain wrappers or styling props.

## Test selectors

Pass a consumer-owned `data-testid` to opt into test selectors. Components use `partTestId(base, part, ...keys)` for generated parts. It returns `undefined` when the base is absent; otherwise it joins the base, part, and URL-encoded keys with hyphens. It encodes keys with `encodeURIComponent(String(key))`.

```tsx
import { Input, partTestId } from '@itclabs/react-ui';

export const fieldSelectors = {
  control: 'profile-name',
  root: partTestId('profile-name', 'root'),
  label: partTestId('profile-name', 'label'),
  hint: partTestId('profile-name', 'hint'),
};

export const rowSelector = partTestId('records', 'row', 'a/b');
// rowSelector is "records-row-a%2Fb".

export function Example() {
  return (
    <Input
      data-testid={fieldSelectors.control}
      label="Display name"
      hint="Enter the name shown on your profile."
    />
  );
}
```

For this Input, the base ID targets the native input; the wrapper, label, and hint receive the derived IDs shown above. Parts rendered conditionally only receive selectors when present. Other components define their own parts and key structure; inspect their API or source before selecting them. Test IDs do not replace accessible labels or change styling and behavior.
