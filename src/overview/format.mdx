# Format helpers

Use **`useFormatters()` from `@itclabs/react-ui/hooks`** in React components to inherit the current UIProvider locale automatically. Switching provider locale updates formatting without remounting children. Defaults can be customized for the hook or one function call. Currency denomination remains explicit; changing the interface language must not change USD into VND.

## Automatic locale in UI components

```tsx
'use client';

import { useFormatters } from '@itclabs/react-ui/hooks';
import { DateFormat } from '@itclabs/react-ui/format';

export function Summary() {
  const { formatNumber, formatCurrency, formatDate } = useFormatters();

  return (
    <dl>
      <dt>Quantity</dt>
      <dd>{formatNumber(1234567.89)}</dd>
      <dt>Price</dt>
      <dd>{formatCurrency(19.9, 'USD')}</dd>
      <dt>Calendar date</dt>
      <dd>{formatDate('2026-11-06', DateFormat.DMY)}</dd>
      <dt>Custom format</dt>
      <dd>
        {formatDate('2026-11-06T08:30:00Z', 'dd/MM/yyyy HH:mm', {
          timeZone: 'Asia/Ho_Chi_Minh',
        })}
      </dd>
    </dl>
  );
}
```

## Typed custom defaults and per-call overrides

Options use exported TypeScript types: `UseFormattersOptions`, `LocaleFormatters`, `FormatNumberOptions`, `FormatCurrencyOptions`, `FormatDateOptions` (Intl) and `FormatDatePatternOptions` (patterns). `CurrencyCode` suggests common denominations while accepting other valid codes. An explicit per-call option wins over hook defaults; hook `locale` wins over UIProvider. These are local bindings, not shared global configuration.

```tsx
'use client';

import { useFormatters, type UseFormattersOptions } from '@itclabs/react-ui/hooks';
import {
  DateFormat,
  type FormatNumberOptions,
  type FormatDatePatternOptions,
} from '@itclabs/react-ui/format';

const defaults = {
  timeZone: 'Asia/Ho_Chi_Minh',
  fallback: 'Not available',
} satisfies UseFormattersOptions;
const precision = { maximumFractionDigits: 2 } satisfies FormatNumberOptions;
const customDate = {
  locale: 'en-US',
  timeZone: 'UTC',
} satisfies FormatDatePatternOptions;

export function CustomSummary() {
  const { formatNumber, formatCurrency, formatDate } = useFormatters(defaults);

  return (
    <div>
      <p>{formatNumber(1234.567, precision)}</p>
      <p>{formatNumber(1234.5, { locale: 'en-US' })}</p>
      <p>{formatCurrency(19.9, 'USD', { currencyDisplay: 'code' })}</p>
      <p>{formatDate('2026-11-06T08:30:00Z', DateFormat.DMY_TIME, customDate)}</p>
    </div>
  );
}
```

## Date patterns

`formatDate(value)` defaults to **`dd/MM/yyyy`**. Choose a predefined `DateFormat` for editor suggestions, or pass a custom date-fns pattern. `DateFormatPattern` keeps those suggestions while accepting free-form strings. TypeScript checks option names and value types; a free-form pattern's meaning is validated by date-fns at runtime. Use lowercase `yyyy` and `dd`, not week-year/day-of-year `YYYY` and `DD`.

| Enum                     | Pattern               |
| ------------------------ | --------------------- |
| `DateFormat.DMY`         | `dd/MM/yyyy`          |
| `DateFormat.YMD`         | `yyyy-MM-dd`          |
| `DateFormat.DMY_TIME`    | `dd/MM/yyyy HH:mm`    |
| `DateFormat.DMY_SECONDS` | `dd/MM/yyyy HH:mm:ss` |
| `DateFormat.TIME`        | `HH:mm`               |

For pattern month/day labels, built-in locale resolution supports Vietnamese and English; other locale codes fall back to English labels. Supply a full date-fns `Locale` using `dateLocale` in hook defaults or the third pattern-options argument for other languages. This is independent of the provider's optional partial calendar locale. Intl formatting supports the runtime's native locale catalog.

The existing Intl options signature is also supported: `formatDate(value, { dateStyle: 'long', locale: 'vi-VN' })`. For patterns, use `formatDate(value, 'dd MMMM yyyy', { locale: 'en-US' })`. Do not pass an Intl options object as the third pattern argument.

## Pure helpers for server and non-React code

Import **`formatDate`, `formatCurrency`, `formatNumber` and their types from `@itclabs/react-ui/format`**. They have no React dependency or client directive. A pure function cannot read React context; it defaults to `vi-VN` and accepts explicit locale overrides. There is no navigator detection or global locale mutation, so independent requests cannot change each other's formatting.

```tsx
import {
  formatDate,
  formatCurrency,
  formatNumber,
  DateFormat,
} from '@itclabs/react-ui/format';

export function ServerSummary() {
  return (
    <dl>
      <dt>Quantity</dt>
      <dd>{formatNumber(1234567.89, { locale: 'vi-VN' })}</dd>
      <dt>Price</dt>
      <dd>{formatCurrency(19.9, 'USD', { locale: 'en-US' })}</dd>
      <dt>Day</dt>
      <dd>{formatDate('2026-11-06', DateFormat.DMY)}</dd>
      <dt>Localized date</dt>
      <dd>{formatDate('2026-11-06', { locale: 'en-US', dateStyle: 'long' })}</dd>
    </dl>
  );
}
```

## Missing values and time zones

Numbers accept number, null or undefined and support native Intl number options. Currency requires a code such as `VND`, `USD` or `EUR`; its fraction defaults follow Intl. Formatting does not convert currencies or provide financial arithmetic.

Dates accept Date, epoch milliseconds, an ISO calendar date (`YYYY-MM-DD`), or an ISO datetime with `Z`/an explicit `±HH:MM` offset, null or undefined. Ambiguous local strings and datetimes without an offset are rejected. Invalid calendar dates such as February 30 use the fallback.

All helpers default to fallback `—`; null, undefined, invalid dates and nonfinite numbers are missing. Zero and epoch `0` are valid values. Invalid configuration (currency, locale, time zone, date pattern or incompatible Intl options) throws instead of being silently hidden as missing data.

Date-only strings preserve their calendar day in UTC, even when another timeZone is supplied. Instants default to UTC; set timeZone in hook defaults or per call for application-local display. Locale follows the provider; timeZone is a separate explicit setting. Original numeric values and Date objects are not mutated.

## Bundle behavior

Pattern formatting reuses the package's existing date-fns and date-fns/tz peers. The entire format entry including patterns and Vietnamese/English date labels measures approximately 9.7 KB gzip; a named formatNumber import is about 155 bytes gzip. Unused format modules and optional theme presets do not enter the Button bundle. Run `node scripts/measure-feature-bundles.mjs` to reproduce. These are production ESM JavaScript transfer measurements, not installed-package sizes.
